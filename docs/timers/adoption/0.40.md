# Adopting Timers 0.40 from 0.39

This checklist covers the published 0.40 contract. It is guidance for consumer
owners, not a record of completed Canic or database qualification. The
[Timers ledger](../../../releases/timers/CHANGELOG.md#0400---2026-11-04)
records the change; dated [Canic evidence](canic.md) keeps its original scope.

## Align the dependency graph

1. Select Timers 0.40 in the consumer-owned root catalog. Align every runtime
   supplier linked into the same canister so it resolves one Timers package ID;
   review private integration manifests and lockfiles as well as the root lock.
   Native test harnesses can have distinct graphs, but each composed canister
   must retain the single timer provider and executor.
2. Keep Runtime in the 0.19 family with its exact matching executor guard.
   Timers 0.39 already uses Runtime 0.19; consumers still on Runtime 0.18 need
   to align their Runtime/Endpoint suppliers first. Preserve the compiler floor
   and the consumer's actual target/feature selections. Never bypass singleton
   guards to admit mixed runtime families.
3. Align direct Metrics dependencies with Timers' public Metrics 0.29 types.
   The 0.40 breaking change is the recorder contract: Serde, mean/delta/interval
   queries and public reconstruction constructors are removed. Report owners
   keep their DTOs, bounded codecs, validation and arithmetic, including absent
   samples and overflow quality. A second Metrics version may compile when no
   types cross the boundary; it does not make 0.28 and 0.29 recorders interchangeable.
4. Review native harness changes separately. This repository qualifies Testkit
   0.84's `ic_testkit::pocket_ic` client. Testkit and Storage/Wire qualification
   selections are not extra dependencies required by the Timers library.

## Preserve scheduling and custody

Registration, scheduling decisions, callback ownership and lifecycle ordering
remain unchanged from 0.39. Audit the
[six registration/reconciliation capabilities](../../../crates/ic-timers/README.md#registration-and-reconciliation-capabilities),
including `register_watchdog`, in the consumer's approved owner inventory.
Custody checks also cover aliases and macro-contained use; no new wrapper or
export scanner is required by this update.

Keep one retained claim per fixed owner and reconcile it from durable demand
before downstream application hooks. A full registration registry still permits
an existing retained claim to arm, cancel and rearm; provider admission and checked
deadlines remain separate failure boundaries. An idle or stopped declaration
does not dispose of uncertain application effects. Retry budgets, funding
decisions and safe effect disposition stay with the consumer.

## Qualify the consumer's selected inputs

- Check the actual production Wasm and native harness dependency graphs. Bind
  observations to the manifests, locks, compiler and feature selections used;
  repeating an old passing command after a lock change requires fresh evidence.
- Run focused native tests and warning-denied lint for changed Metrics/reporting
  adapters, retained-owner control and lifecycle reconstruction. Check the
  consumer's real Wire/JSON report roundtrips, including empty and overflow cases.
- Build the affected canister artifacts and explicitly select the consumer's
  installed tests for scheduling admission before reservations, synchronous
  reconstruction before user hooks, callback abandonment/rearm, exact replay
  and bounded retry custody. Run any still-pending issue acceptance against those
  same artifacts; native tests do not establish IC recovery.
- Qualify private consumers against their own selected locks/artifacts. Retain
  prior logs and failures with their original source. Update readiness only when
  the changed scoped inputs and required acceptance match; this checklist does
  not establish cross-release persisted-data migration or authorize delivery.

The upstream native capacity regression can be selected with
`bash scripts/dev/minimum-rust.sh cargo test -p ic-timers --lib --locked --offline -- runtime::tests::capacity`.
It protects retained owner reuse for all three policies. It does not replace the
consumer's installed suspension, reservation or upgrade tests. See the
[development guide](../development.md) for this repository's separate installed
qualification commands and source-bound evidence limits.
